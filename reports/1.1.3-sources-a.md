Each module exports `SOURCE_KEY`, `BASE`, `is_<name>_host(host)`, `pub mod browse`
(`catalog`, `filters`, `series`), `pub mod resolver` (`resolve`) and re-exports the
three browse functions plus `resolve` at module level.

| Module | `SOURCE_KEY` | `BASE` |
|---|---|---|
| `animecube_live` | `animecube_live` | `https://animecube.live` |

All three `resolve()` functions set `source` to their key, `platform` to
`dailymotion` when the resolved target is a Dailymotion video/player URL (empty
otherwise, reserved for direct CDN URLs), `video_id` from
`crate::media_ids::extract_video_id(page_url)` (stable page identity for the
archive; `ac-…` for animecube.live, `web-…` for DongSub/LMAnime until hosts are
registered centrally), and `is_hls` via the shared `is_hls_url`.

## Real URL patterns discovered (verified live, 2026-11-28)

### animecube.live
- `/` and `/catalog` render poster cards: `<article class="group relative min-w-0">`,
  `<a href="/watch/<episodeCode>">`, `<img alt="<title>" src="…">`,
  `<span class="poster-label" data-tone="ongoing">Airing</span>`.
- Public JSON (no key, no login): `/api/catalog` (full item list),
  `/api/search?q=<query>` (search), `/api/watch/<episodeCode>/context`
  (anime metadata + `episodeGroups` + episodes). These are the primary browse
  inputs; the HTML card parser is kept as a fallback.
- Series URL: `/title/<animeCode>`; episode URL: `/watch/<episodeCode>`.
  `/series/<code>` is a 404; `/anime/<code>` just renders home.
- Playback is **not** anonymous: `/api/anime-sources-versions` → HTTP 410,
  `/api/watch/<code>/sources` → HTTP 403, `/api/download/ticket` (POST) →
  HTTP 401 `auth.login_required`. `/api/watch/<code>/downloads` returns metadata
  but only a `releaseVersion`, not a media URL.

### dongsub.net (Blogger)
- Series posts: `/YYYY/MM/<slug>.html` (e.g. `/2025/05/renegade-immortal.html`).
  The A-Z list `/p/az-list.html` (and the home "Jadwal Rilis" widget) has stable
  series links with titles.
- Series post body contains `var label_episode = "Renegade Immortal";` and a
  synopsis in `<div class="sinoposis">`; episodes are loaded from the Blogger
  feed `/feeds/posts/default/-/<label>?alt=json&max-results=50` (50 entries for
  the real label; the static `/search/label/…` HTML shows only 5).
- Search/label pages: `/search?q=<query>`, `/search/label/<label>?&max-results=10&start-index=N`.
  Post cards: `<article class='post'><h3 class='post-title'><a href=…>`.
- Episode page player: `<select id="selectServ"><option id="servDefault"
  value="https://geo.dailymotion.com/player/x110cm.html?video=<id>">Server 1</option>`;
  the `<iframe src="">` is filled by JS.

### lmanime.com (WordPress, same theme as animekhor.org)
- Catalog `/anime/?status=&type=&order=update`, paging `/anime/page/N/`;
  genres `/genres/<slug>/` + `/genres/<slug>/page/N/`; search `/?s=<query>` +
  `/page/N/?s=<query>`.
- Cards: `<article class="bs">` + `<a href=… itemprop="url" title=… rel=…>`,
  `<img data-src=…>`, `<div class="typez …">`, `<span class="epx">`.
- Series: `<h1>`, `<div class="spe">` metadata, `<div class="genxed">` genres,
  `<div class="eplister"><ul><li><a href=…>` episodes with `epl-num`,
  `epl-title`, `epl-date`.
- Episode player: `<div class="player-embed" id="pembed"><iframe
  src="https://geo.dailymotion.com/player/xofxc.html?video=<id>">`, plus mirror
  `<select class="mirror"><option value=…>`.

## Parser / resolver behavior

- Parsers are pure (regex + `serde_json` for the public JSON payloads), compiled
  patterns are cached in a `OnceLock<Mutex<HashMap<…>>>`, and an invalid pattern
  is treated as "no match" rather than panicking. No `unwrap()`/`expect()` in
  production code.
- Browser-style UA comes from the shared `fetch_text`; no frontend fetch and no
  secrets. Cache keys include mode, page and URL; `filters`/`series` use the same
  disk cache with caller-supplied TTL and `refresh`.
- Dailymotion normalisation handles `geo.dailymotion.com/player/<id>.html?video=<v>`,
  `dailymotion.com/embed/video/<v>`, `dai.ly/<v>` and plain
  `dailymotion.com/video/<v>` → `https://www.dailymotion.com/video/<v>`.
- Missing player/series data produces `AppError::source_with` with a friendly
  message plus the requested URL in `detail` (copyable in the UI).
- animecube.live's resolver returns a direct target if the page ever exposes an
  embed/direct `.mp4`/`.m3u8`, otherwise fails early with the specific
  "protected API / sign in" message instead of handing a raw page to yt-dlp.

`Requested format is not available` because Dailymotion exposes video-only HLS
formats plus separate audio; the default format selector and `--simulate` both
work. The downloader should keep its existing `bestvideo+bestaudio/best` style
selection rather than literal `best`.

## Caveats / handover notes

- `video_id` for DongSub and LMAnime is currently `web-<digest>` because
  `media_ids.rs` does not yet know those hosts. If the main agent registers them
  there, the archive tag will become source-specific; no code in these modules
  needs to change (they call `extract_video_id`).
- animecube.live is browse-only in practice: Explore/series work, downloads
  fail with a friendly error until a signed-in source resolution path exists.
  Leave it out of automatic fallback/replacement until then.
- The `animecube_live` catalog uses the JSON API; if it is ever removed, the
  HTML card parser in `browse.rs` is the fallback (`fetch_text` + `parse_cards_html`).
- Fixtures were trimmed from real responses to keep them reviewable; numeric
  entities, Unicode titles and Blogger arrow prefixes are preserved.
